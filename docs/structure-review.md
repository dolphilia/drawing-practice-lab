# 初期構成・雛形のレビュー

確認日：2026-10-01

## 結論

既存のトップレベル構成を維持する。外部資料、横断的な分析、技能、メソッド、実行手順、練習計画、検証、日誌が分かれており、資料収集から方法開発までの役割を表現できている。現段階でデータベースや細かい分類を増やす必要はない。

不足していたのは、文書間の運用の整合性と「どの条件で役立ったか」を後から判断するための記録だった。

## 確認した問題と反映内容

| 元の状態 | 起こり得る問題 | 反映した改善 |
| --- | --- | --- |
| 共通 status は4種類、実験だけ未定義の `done`、日誌は別形式 | 文書の完成と効果の確認が混同される | 文書別の状態と日誌の例外を定義 |
| 「効果を確認できたら stable」だけ | 一度の成功や感想で確立扱いになる | 対象・条件、別日の確認、保持・転移、限界を採用基準に追加 |
| 実験は前後の画像と自由記述が中心 | 条件差や採点基準の後付けを追えない | 事前計画、比較条件、実測値、欠測・変更、別の説明の欄を追加 |
| 資料には出典欄があるが、該当箇所や確認範囲がない | 要旨だけの情報と全文確認を区別できない | 公開年・確認日・資料の性質・ページ等・確認範囲を追加 |
| 手順へのリンクだけで版がない | ドリル更新後に過去の実験条件が不明になる | メソッド・ドリル・プログラムの版と、実施条件の控えを導入 |
| 画像をすべて Git 管理外にする | 共有時に比較の根拠が見えず、Git から復元もできない | ローカル方針を維持し、共有用 `assets/evidence/` と本文の結果記録を追加 |
| 雛形に未作成リンクがある | コピー後もリンク切れが残りやすい | 雛形の架空リンクを除去し、保存先・相対パスの説明を追加 |
| スキル図の枝が「色」の下につながる | 色から全分野に進む固定順序に見える | 相互に関連する分類へ修正し、観察・比較・自己評価を追加 |
| ワークフローにプログラムと日誌の運用説明が少ない | 全文書を作らないと始められないように見える | 最小の始め方と、省略・往復できる流れを明示 |

## 調査した根拠と設計判断

- [Soderstrom & Bjork (2015) の本文](https://bjorklab.psych.ucla.edu/wp-content/uploads/sites/13/2016/11/soderstorm_ra_learningvsperformance.pdf)：練習中の遂行と保持・転移の区別を参照。[確認範囲を記した資料メモ](../references/articles/soderstrom-bjork-2015-learning-versus-performance.md)を作成した。
- [Newell ほか (1990) の要旨](https://pubmed.ncbi.nlm.nih.gov/15117661/)：描画課題での目標情報とフィードバックの作用を参照。[要旨のみと明記した資料メモ](../references/articles/newell-1990-drawing-feedback.md)を作成した。

これらは評価設計の参考であり、ディレクトリ構成の正しさや独自メソッドの有効性を実証する根拠ではない。状態の分離、版管理、最小限の日誌は、本リポジトリを継続して使うための設計判断である。

## 現段階では追加しないもの

- 技能カテゴリの細分化：実際の資料やドリルが増えてから分ける。
- 独立した評価課題ディレクトリ：当面は技能・ドリルに基準、実験に実施時の条件を置く。複数実験で同じ課題を再利用する必要が生じたら切り出す。
- ID 管理システム・データベース・CI：当面は説明的なファイル名、相対リンク、版で運用する。
- 大量のサンプルや検証済みメソッド：練習実績がない段階では作らない。

次は、関心のある技能を1つ選び、資料メモ・実行可能なドリル・日誌の小さな一巡を試す。その際に記入しづらい項目を調整する。
