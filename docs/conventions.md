# 運用ルール

## ファイルと分類

- ファイル名は英小文字のケバブケース：`gesture-drawing.md`
- 実験・日誌は `YYYY-MM-DD` を先頭にする。例：`experiments/2026-10-01_gesture-30s.md`、`logs/2026/2026-10-01.md`
- 同じ日の実験・日誌を分ける場合は説明的な名前を付ける。年月の分類は件数が増えてから追加する。
- 資料は媒体別（`books` / `videos` / `articles` / `artists`）、技能とドリルは主な目的別に置く。論文は `references/articles/` に含める。
- 分析は `research/topics/`（テーマ）、`research/comparisons/`（比較）、`research/learning-science/`（学習研究の応用）に分ける。
- 複数分野にまたがる文書も本体は1つにし、他の分野からリンクする。新しい分類は既存分類では探しにくくなってから、技能とドリルの両方に追加する。

## フロントマター

資料・分析・技能・メソッド・ドリル・プログラム・実験には `title`、`status`、`tags`、`created`、`updated` を記入します。日誌は負担を抑えるため `date`、`duration_minutes`、`exercises` だけで構いません。README・運用ガイド・用語集・スキルマップには必須にしません。

```yaml
---
title: "ジェスチャードローイングの仮説"
status: draft
tags: [figure, gesture]
related: []
created: 2026-10-01
updated: 2026-10-01
---
```

日付は `YYYY-MM-DD`、時間は分単位の数値、日数は日単位の数値にそろえます。未記入の値は `null`、未登録のリストは `[]` とします。テンプレートの `YYYY-MM-DD` は作成時に置換します。`tags` は英小文字のケバブケースで、既存の表記を優先します。

### 文書ごとの status

| 文書 | 使用できる値 | 意味 |
| --- | --- | --- |
| 資料・分析・技能 | `draft` / `ready` / `archived` | 下書き / 読み返せる状態 / 現在は使用しない |
| ドリル・プログラム | `draft` / `testing` / `ready` / `archived` | 作成中 / 試行中 / 実行できる手順として整備済み / 使用停止 |
| メソッド | `draft` / `testing` / `stable` / `archived` | 仮説 / 検証中 / 条件付きで採用 / 使用停止 |
| 実験 | `draft` / `testing` / `done` / `archived` | 計画中 / 実施中 / 結果・考察を記録済み / 中止・取り下げ |

`ready` は内容の真偽や練習効果の証明ではありません。`done` は実験の成功を意味しません。効果なし・判断不能も完了結果として残します。`archived` には理由と、あれば後継文書を記載します。状態別のフォルダ移動を行うのはメソッドだけです。

## 書き分けと根拠

- `references/`：著者が何を主張したか、確認した範囲、ページ・節・タイムスタンプを残す。資料に書かれていること自体を、検証済みの事実とは扱わない。
- `research/`：問い、複数資料の一致・相違、自分の解釈、未解決点を記載する。
- `skills/`：何ができれば到達したと判断できるかを定義する。
- `methods/`：原理の仮説、適用範囲、外部資料と自分の検証結果を記載する。
- `exercises/`：再実行できる条件・手順と、結果の見方を記載する。既存の練習法にも出典を付け、独自開発とは区別する。
- `programs/`：順序、頻度、見直し時期を定める。ドリルの手順は複製せずリンクする。
- `experiments/`：開始前の計画と、その後の観察・解釈を分ける。
- `logs/`：実際の実施量、観察、次の一手を短く残す。毎回実験にする必要はない。

外部の研究結果・指導者の経験則・自分の観察・未検証の仮説を区別します。要旨だけを確認した資料はその旨を書きます。架空の実施結果や採点値を埋めず、説明用の数値には「例」と明記します。

資料ノートには `evidence_kind`（根拠の種類）、`domain`（対象分野）、`verification`（確認範囲）を記載します。値と読み方は [資料の評価・分類方針](evidence-policy.md)を参照してください。媒体別の保存場所と、根拠による分類は独立しています。新規資料を追加したら [資料一覧](../references/README.md)も更新します。

## リンクと版管理

- 本文の Markdown リンクとフロントマターのパスは、いずれも**保存先ファイルからの相対パス**とする。
- `related`・`target_skills`・`prerequisites`・`exercises` はパスのリスト、`method`・`experiment` は単一パスまたは `null`。主要な関係は本文にもクリックできるリンクを置く。
- テンプレート内のパス例はコピー先を想定したもの。移動後に確認し、未作成ファイルへのリンクは作らない。
- メソッド・ドリル・プログラムには整数の `version` を付け、効果や再現性に関わる原理・手順・時間・評価方法の変更で増やす。誤字修正では増やさない。
- 実験には使用したメソッドとドリルの版を記録する。Git のコミットを記録できる場合は併記し、未コミットの手順は実験本文に必要な条件を写す。終了後にリンク先が更新されても実施条件を追えるようにする。
- 移動・改名時には旧パスを検索し、本文とフロントマターの参照を更新する。ファイル名はできるだけ維持する。

## メソッドの採用と見直し

1. `methods/drafts/` に `draft` として作成する。
2. 実験計画を作り、開始したら同じ場所で `testing` にする。
3. [採用基準](evaluation.md)を満たしたら、判断理由・対象範囲・検証へのリンクを記入し、`methods/stable/` に移して `stable` にする。
4. 反証や大きな条件変更があれば `methods/drafts/` に戻して `testing` にする。使用停止の場合は `methods/archived/` に移す。

`testing` 用のフォルダは追加しません。移動先はいずれも同じ深さなのでルート方向の相対パスは保てますが、その文書を指すリンクは更新が必要です。

## 画像・共有素材

ローカルの練習画像は `images/`、共有する自作の図・比較画像・練習シートは `assets/` に置きます。保存・出典・バックアップの扱いは [画像の保存方針](../images/README.md)を参照してください。
