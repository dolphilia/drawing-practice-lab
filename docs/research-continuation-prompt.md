# 調査計画の継続用プロンプト

更新：2026-10-02。現在の進捗はこの文書へ複製せず、[計画書](research-plan.md)と、そこから辿れる最新の収集記録で管理します。同じリポジトリを開いた会話で、次の短い指示を繰り返し使えます。

```text
docs/research-continuation-prompt.md の「継続用プロンプト本文」に従い、現在のリポジトリから再開位置を確認して、調査計画の次の作業単位を完了してください。調査・分類・保存・分析への反映・点検・次回への引き継ぎまで実行してください。
```

別の環境へ本文を貼る場合は、このリポジトリを読み書きできる状態で使用します。時間・テーマを指定したい場合だけ追加指示を添えます。再開のたびに段階名・日付・資料数を書き換える必要はありません。これは再実行用の指示であり、定期実行の設定ではありません。

## 継続用プロンプト本文

```text
このリポジトリの調査計画を、現在の進捗から継続してください。

目的は、信頼性を区別した資料から、イラストの練習方法と評価方法を開発できる状態にすることです。キャラクターイラストを重点としつつ、学習科学、既存教材、隣接分野も計画に沿って扱ってください。計画の説明や提案で終わらず、今回選んだ作業単位について、調査・選別・保存・統合・点検・引き継ぎまで実行してください。

1. 現在の状態から再開する

- 適用されるリポジトリの指示と作業ツリーの変更を確認し、既存の未コミット作業を保全してください。
- docs/research-plan.md、docs/evidence-policy.md、docs/conventions.md を読み、references/README.md と research/README.md から対象資料を特定してください。評価を扱う場合は docs/evaluation.md も確認してください。
- 計画書が指す最新の収集記録の終了欄と、今回の対象ノートを読んで、完了・途中・保留・次の判断を把握してください。同日にも複数の記録があるため、ファイル名の日付だけで新旧を決めないでください。
- 会話での最新の訂正・依頼を反映し、過去の発言だけで進捗を推測しないでください。計画と保存済み成果物が食い違う場合は、確認範囲を確かめて必要な箇所を修正してください。
- 全資料を毎回読み直さず、索引と引き継ぎから必要な箇所へ進んでください。

2. 今回、何を判断できるようにするか決める

- 計画書の次の一手を出発点に、優先順位・依存関係・未解決点から一つの問いを選んでください。
- 最初の進捗報告で、対象の問い、今回判断したいこと、保存する成果物、区切る条件を簡潔に示し、そのまま着手してください。通常の資料探索・分類・リポジトリ内の編集は、この依頼の範囲として進めてください。
- 作業単位は、原典の方法・結果の確認から分析への反映まで一巡できる大きさにしてください。ページ一つの閲覧、資料数の増加、計画書の更新だけを完了条件にしないでください。
- すでに完了した作業は、新しい訂正・矛盾・適用条件の変更がない限り繰り返さないでください。優先順位を変える場合は理由を残してください。

3. 根拠と確認範囲を分けて調べる

- 新たな外部の事実を確認するときは、実際に検索・取得・閲覧してください。著者・出版社・大学等の一次資料を優先し、問いに応じて引用元、追試、批判、訂正、効果なし・転移しない結果も探してください。
- 日付、検索先、実際の検索式、言語・年の条件、確認範囲、取得制限を記録してください。直接閲覧だけの回はその旨を記し、実施していない検索を埋めないでください。
- 本文、要旨、検索抜粋、図表の確認を分けてください。画像内の手順を使う場合は画像も確認し、数値は該当ページ・節・表・図と対応させてください。
- evidence_kind、domain、verification は既存の方針に従って設定してください。手順の出典として確かなことと、練習効果が実証されていることは別に判断してください。人気・知名度・査読・読了のいずれも、それだけで効果の保証にしないでください。
- 研究が直接示す結果、著者の経験則、他分野からの類推、このリポジトリの未検証案を区別してください。別掲載版、同じ標本、レビューに含まれる原著を独立した裏付けとして二重計上しないでください。
- 評価では、採点の一致、妥当性、作画自体の変動、直後の遂行、保持、転移を区別してください。目標図参照と手順参照、途中テスト、対象者・課題・比較条件も確認してください。
- 時間については、作画・説明・評価、1回の量・頻度・総期間、予定量・実施量、最終練習から評価までの間隔を分けてください。「その量で評価した」を「必要最低量が判明した」に置き換えないでください。

4. 取得できない資料を管理し、独立した作業を進める

- 本文が取得できない場合は、利用可能な出版社・著者版・機関リポジトリ等の代替経路を確認してください。確認できなければ、試した経路、未確認箇所、結論への影響、再開条件を残してください。
- 新しい経路や必要性の変化がないまま、同じ取得失敗を繰り返さないでください。保留資料に依存しない問い・資料へ進んでください。
- 限定された検索で見つからなかった場合は、その範囲を明示してください。根拠の不足を「無効」や「研究が存在しない」と言い換えないでください。
- ユーザー固有の情報が不可欠な場合は、必要な点だけを尋ね、回答に依存しない作業を続けてください。

5. 知見を保存し、判断へつなげる

- 個別資料は templates/reference.md を参考に references/ の適切な場所へ、横断的な解釈は research/ へ保存してください。既存ノートの更新を優先し、原典の長文・図版の転載で資料を増やさないでください。
- 今回の検索・選別・確認・保留・判断を templates/collection.md に沿って research/topics/ の新しい収集記録へ残してください。実際の日付を使い、同日の既存記録を上書きしない名前にしてください。
- 新しい資料や訂正が既存の比較表・評価案・仮説をどう変えるかを反映してください。結論が変わらない場合も、何が確認され、何が依然不明かを記してください。
- 原典の手順を独自に簡略化・変更するときは、変更点と理由を明記してください。資料不足の穴埋めとして未検証の設計を量産せず、次の検証に必要なものに絞ってください。
- 手順と評価が揃った候補は、計画に従ってメソッド・ドリル・実験計画の草案へ渡してください。実際の作品・参加者・実施記録がない状態で、練習・採点・保持テストを実施済みとはしないでください。ready と効果の実証、draft と stable を区別してください。

6. 点検し、次回が迷わない状態にする

- 変更した資料の出典、重要な数値・単位・測定点、根拠の分類、確認範囲、内部リンク、必要なメタデータ、索引と件数の整合性を点検し、問題を修正してください。新規ファイルも対象にしてください。
- 前回の一時スクリプトやツールが残っていると仮定せず、利用できる方法で変更に見合う点検を実施してください。未実行の検査を通過済みと記録しないでください。
- 計画書の「現在の進捗」と対象の状態を更新してください。過去の収集記録は当時の確認範囲を保ち、訂正が必要な場合は追記で経緯を残してください。
- 最新の収集記録の末尾に、次の引き継ぎを保存してください。
  ・今回判断できたことと、それを支える資料・成果物
  ・完了／途中／保留の範囲
  ・残件と、保留を再開する具体的な条件
  ・次の問いを一つ、その最初の取得先または作業、期待する成果物、区切る条件
  ・最初の取得先が使えない場合に進める代替作業
- 作業時間は実際に測れた場合だけ記載し、待ち時間を含むかを明示してください。測れていない時間や前回の件数を推定で埋めないでください。

7. 適切な単位で区切る

- 今回決めた問いについて、確認結果または保留理由が揃い、分析・保存・点検まで終わるまで進めてください。関連する未処理の反映・点検を「次回」に送らないでください。
- 段階の完了条件を満たしたら、保留を残したまま進めてよいかを判断し、次段階へ引き継いでください。全件精読を待って同じ段階に留まり続けることも、条件を満たさず完了扱いにすることも避けてください。
- 実行上限・ユーザーの中断・必要情報の不足で途中終了する場合は、最後に確認した箇所と未保存・未点検の有無を残してください。「今回の作業単位が完了」と「計画全体が完了」を区別してください。
- 最後は日本語で、今回進んだ判断、主要な保存先、残る制約、点検結果、次の一手を簡潔に報告してください。再開時は計画と最新記録を読み、この流れを続けてください。
```

## 設計の考え方

計画・成果物・完了条件・判断履歴をファイルに残す構成は、[OpenAI公式の長期タスクの解説](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)を参考にしました。研究資料の分類、時間の解釈、保留の扱いは、このリポジトリの[資料方針](evidence-policy.md)と[調査計画](research-plan.md)に合わせた独自の指示です。プロンプトの効果を比較実験で検証したものではありません。
