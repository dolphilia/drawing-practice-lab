# 調査計画を完了まで進める長期目標用プロンプト

更新：2026-10-02。[継続用プロンプト](research-continuation-prompt.md)の調査品質を維持しながら、作業単位を繰り返して[計画書](research-plan.md)の調査・設計フェーズ全体を進めるための指示です。

対象は、学習・評価、既存メソッド、キャラ絵、隣接分野の調査を統合し、少なくとも一つの狭い描画技能について探索的な実験へ渡せる状態を作ることです。リポジトリの大きな目的である「効果の確かなお絵描きメソッドの確立」には、その後の実践と検証も必要です。このプロンプトで調査が完了しても、メソッドが実証されたことにはなりません。

## そのまま使える開始指示

同じリポジトリを開いた会話で、次を送ってください。この文書を作成・閲覧するだけでは Goal を開始しません。

```text
docs/research-long-term-goal-prompt.md の「長期目標用プロンプト本文」に従って、調査計画の完遂を長期目標として設定し、現在の進捗から作業を開始してください。個々の作業単位や段階の終了を途中保存として扱い、目標全体の完了条件を検証できるまで、次の優先作業を自ら選んで継続してください。
```

Codex の Goals は、目標を会話の複数ターンにわたって保持する仕組みです。利用可能な環境ではこれを使います。プロンプトだけでは、利用上限や外部データ待ちを越える連続実行は保証できません。[公式の Goals 解説](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)

## 長期目標用プロンプト本文

```text
このリポジトリの調査計画を完遂することを長期目標として設定し、現在の進捗から実行してください。

長期目標：
docs/research-plan.md の段階A〜D、Q1〜Q6について必要な調査・分類・統合を行い、学習科学、評価と練習量、既存のお絵描きメソッド、洞田創を含むキャラクターイラスト教材、隣接分野からの転移を整理する。そのうえで、少なくとも一つの狭い描画技能について、練習手順・根拠の限界・評価方法・評価時期を説明し、実施可能な探索的実験計画へ渡せる状態にする。

1. 目標と再開位置を確定する

- 適用される指示、作業ツリー、計画書、最新の収集記録を確認し、保存済みの成果物から再開位置を判断してください。既存の未コミット変更を保全してください。
- Goal 機能が利用できる場合は現在の状態を確認し、同じ目標が活動中なら引き継いでください。未完了の別目標を上書きせず、競合がある場合だけ必要な確認をしてください。新しい目標が必要なら、この長期目標と以下の完了条件を登録してください。ユーザーが指定していないトークン予算は設定しないでください。
- docs/research-continuation-prompt.md の調査・分類・保存・点検の指示を適用してください。ただし第2節の「今回」と第7節の「区切る」は、一つの作業単位の途中保存を意味します。一つの単位の完了では作業を終了せず、本プロンプトの継続・完了条件に従ってください。
- 計画書の「現在の進捗」に、この目標の対象範囲と完了条件の確認欄を設けてください。既存欄がある場合は更新し、進捗の正本を増やさないでください。各条件に、達成・未達・阻害要因と、判断を裏付けるファイルを対応させてください。
- この目標は調査・設計フェーズの完了です。実際の描画実験や効果の実証を済ませた扱いにしないでください。ユーザーが実証までを目標に指定した場合は、その成果物と実データの条件も加え、調査だけで目標を完了しないでください。

2. 全体の完了条件

以下のすべてを成果物で確認できるまで、目標は未完了です。

- 段階A〜Dの完了条件と、計画書末尾の調査サイクルの確認項目を満たしている。Q1〜Q6の各問いに実際の探索・選別記録があり、調べた範囲、得られた結論、反証・適用限界、未解決点を追える。未着手と書いただけでは、この目標の完了条件を満たさない。
- 学習・評価について、採点の一致、作画の変動、妥当性、直後の遂行・保持・転移を区別している。練習量・頻度・総期間・評価間隔を比較し、研究で用いられた量と、最低必要量について言えること、未検証の運用判断を区別している。
- 計画書の重点技能について、教材の手順と効果・評価研究を別々に探索している。洞田創のメソッドは本文・図版・例外・未確認箇所の対応が分かり、少なくとも一つの同じ技能を狙う別の方法と比較できる。人気や著名さを効果の証拠として扱っていない。
- 隣接分野について、元分野の結果、描画への直接の転移データ、このリポジトリの仮説を区別し、描画に応用する条件と限界を説明している。
- 少なくとも一つの狭い技能について、メソッドまたはドリルの草案と探索的な実験計画がある。手順・対象者・比較条件・評価指標・改善の判定・実施量・保持と転移の測定・打ち切り条件を記述している。設計上の暫定値には理由と見直し条件があり、実施を左右する未決事項を空欄のまま「実施可能」としない。
- 出典・分類・確認範囲・重要な数値・内部リンク・索引・重複を点検し、重大な矛盾を修正している。上の各条件に対応する成果物と点検結果を計画書から辿れる。

資料の入手不能や科学的な不確実性をすべて解消することは要求しません。検索範囲、代替経路、結論への影響、再開条件を残し、必要な判断ができる場合に限って保留を残せます。不可欠な手順や評価が決められない状態を、保留欄に記入しただけで達成扱いにしないでください。

3. 作業単位を繰り返す

- 未達条件から、依存関係と判断への影響を踏まえて最優先の問いを一つ選び、調査・選別・原典確認・分析・保存・点検を一巡させてください。
- 一巡したら計画と収集記録へ途中保存し、全体の完了条件を照合してください。未達なら次の問いを選び、そのまま着手してください。「次回はこれを行う」「続けますか」という報告だけで終えないでください。
- 段階をまたぐときも、通常の資料探索・分類・リポジトリ内の編集・草案作成について毎回の許可を求めないでください。新しいユーザーの質問や訂正には対応し、中止・目標変更の指示でなければ目標の作業へ戻ってください。
- 中間報告は、判断が進んだ点、残る不確実性、次に着手することを簡潔に伝えてください。報告やコンテキストの引き継ぎを、目標の停止理由にしないでください。
- 毎回の全資料再読や、結論に影響しない資料数の増加を避けてください。検索の追加によって何の判断を変えたいかを明確にし、主要な問いを確認できたら比較・統合・設計へ進んでください。

4. 阻害要因があっても、進められる仕事を探す

- 取得失敗は代替経路を確認し、新しい経路がなければ保留にしてください。その資料に依存しない問い・比較・既存資料の訂正・設計・点検を進めてください。
- 人の練習、作品、採点、経過時間が必要なら、必要な課題・提出物・時点を具体化し、必要な情報を尋ねてください。その間も独立した作業を続けてください。実施していない実験や数値を生成して穴埋めしないでください。
- すべての有用な作業が外部条件に依存する場合は、阻害要因、試した代替策、未達条件、再開に必要な入力を記録してください。空の処理、同じ失敗の繰り返し、意味のない待機で活動状態を維持しないでください。
- Goal の状態変更は実行環境の規則に従ってください。paused はユーザーが明示的に停止を求めた場合に限り、blocked は環境が定める条件を満たす場合に使ってください。単なる難しさ、時間の長さ、作業単位の終了を理由に停止しないでください。

5. 中断に備えて状態を残す

- 各単位の終了時に、完了／途中／保留、変更した判断、最後に確認した箇所、未保存・未点検の有無、次の具体的な作業と代替作業を保存してください。会話履歴や一時ファイルだけに再開情報を置かないでください。
- 実行上限や利用制限では、可能な範囲で途中保存し、未完了であることを報告してください。上限に近いことを理由に complete にしたり、別の Goal の作成で制限を回避したりしないでください。
- Goal が使えない環境では、その制約を説明し、可能な範囲の作業と再開情報を残してください。無期限の自動継続を約束したり、依頼されていない定期実行を設定したりしないでください。
- 再開時は計画と最新の記録から続け、完了済みの単位を最初から繰り返さないでください。

6. 完了前に全体を検証する

- 全条件を満たしたと思った時点で、条件ごとに対応ファイルと実際の内容を照合してください。チェック欄の記入だけでは検証になりません。
- 抜け・矛盾・未反映の出典・必須の未決事項を見つけたら修正し、必要な作業単位へ戻ってください。終了するために対象範囲を縮めたり、完了条件を緩めたりしないでください。変更が必要なら理由と影響を記録し、ユーザーの目標を維持してください。
- 検証結果を計画書またはそこからリンクする最終記録に残し、すべての必須作業が終わった場合に限って Goal を complete にしてください。
- 最終報告では、達成した目標、主要成果物、点検結果、残る科学的な不確実性を日本語で簡潔に示してください。未完了で終了せざるを得ない場合は、達成報告と区別し、阻害要因と再開条件を示してください。
```

## 設計の根拠

目標、検証可能な完了条件、継続判断を分ける構成は、[OpenAI 公式の Goals 解説](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)を参考にしています。研究に関する条件は、このリポジトリの[調査計画](research-plan.md)、[資料方針](evidence-policy.md)、[評価・検証ガイド](evaluation.md)に合わせた独自の指示です。継続性能や調査品質が実験で検証されたプロンプトではありません。
